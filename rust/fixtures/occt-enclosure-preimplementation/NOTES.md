# Enclosures (M5): native tolerance observations, before any Rust implementation

Source reference `3d097a0328e71b826377d4814ab05ec3c3d23871`, OCCT 8.1.0
built headless with exception checks. `capture.json` records the Rust
revision, the platform and that no Rust enclosure code existed (the working
tree had no kernel changes). `inputs.txt` holds the same explicit OCCT
constructions `compare_brep.py` analyzes, generated by `brep_reference.py`.
`oracle.cpp` is `occt_brep_check_oracle.cpp` as captured, and `native.txt`
holds its third output row per case.

## OCCT source review

* `BRep_Tool::Tolerance` returns the tolerance stored on a vertex, edge or
  face. `BRep_Builder::MakeVertex`, `MakeEdge`, `MakeFace` and `UpdateEdge`
  store the requested value. `BRep_TEdge::UpdateTolerance` and its vertex and
  face counterparts only raise it. A tolerance is a requested upper bound on
  gaps. It is not computed from the geometry unless an algorithm such as
  `BRepLib::SameParameter` or healing grows it.
* `BRepCheck_Vertex` compares each curve end and each curve-on-surface end
  with the vertex point against `max(vertex tolerance, edge tolerance)`.
  `BRepCheck_Edge` runs `BRepLib_ValidateEdge` against the edge tolerance.
* `BRepLib_ValidateEdge` measures the largest distance between the 3D curve
  and the curve on the surface. By default it uses 23 parameters
  (`myControlPointsNumber = 22`). The exact method, used here, maximizes
  numerically (`BRepLib_CheckCurveOnSurface`). Neither is a certified bound.

## What the third row records

For every vertex: its tolerance and its largest distance to the curve ends
of its edges. For every edge: its tolerance. For every use, as built (face,
wire, position): the exact-method deviation for that use's orientation, which
selects the matching pcurve of a seam. For every face: its tolerance.

## Observations

* 52 cases, 1,563 stored tolerances: every one is the requested value
  (`1e-7`, or `0.01` for the 26 entities of the millimetre-scale box). Nothing
  in an explicit construction grows a tolerance, so these say only that OCCT
  stores what it is asked to. Per T6 they are observations, not targets.
* Vertex gaps: 408 of 479 are exactly zero. The 71 others are rounding at
  circle ends (for example `1.28e-15` on `stadium_rotated`) or the mutation
  cases' deliberate moves (`1e-3` on `box_moved_vertex`, `1` on
  `box_zero_length_edge`).
* Use deviations: 1,322 of 1,433 are exactly zero. The 111 others include
  `3.7e-12` from rounding far from the origin (`box_cavity_far`), `1.4e-9`
  for a pcurve shifted below tolerance (`box_pcurve_shift_below_tolerance`)
  and the mutations, up to `5.9` (`cavity_face_uses_outer_edge`). No
  measurement failed.
* The seam uses and seam vertices of cylinders show OCCT's own evaluation
  rounding (about `3.7e-16`). The seamless model has no such entities.

A Rust enclosure must never be smaller than OCCT's measurement of the same
relation on a case valid on both sides, and it must not exceed OCCT's
tolerance for these exactly representable constructions (T6). Either
difference is investigated, never absorbed by loosening a bound.
`compare_brep.py` requires every later run to reproduce these rows:
tolerances exactly, measurements within `1e-15` absolute or `1e-9`
relative, since the exact method's numerical maximization may differ in the
last bits between platforms.
